# Step 1: Setup: virtual environment & dependencies

## Why a virtual environment?

A **virtual environment** (venv) is a private folder of Python packages for one project.
It keeps this project's packages separate from your system Python and from other projects.
That way:

- installing NumPy here can't break another project that needs a different version;
- you never need `sudo pip install`;
- deleting the project folder removes everything cleanly.

## 1.1 Create and activate the venv

From the project root:

```bash
python3 -m venv .venv          # creates the .venv/ folder
source .venv/bin/activate      # Linux/macOS  (Windows: .venv\Scripts\activate)
```

After activation, your prompt shows `(.venv)`, and `python` / `pip` point inside `.venv/`.
Run `deactivate` to leave it.

> Debian/Ubuntu tip: if `python3 -m venv` fails, install the venv module with
> `sudo apt install python3-venv`.

## 1.2 Install only what we need

Dependencies are split into two files:

| File                   | Contains          | Who needs it                         |
|------------------------|-------------------|--------------------------------------|
| `requirements.txt`     | `numpy`           | anyone running the code              |
| `requirements-dev.txt` | the above + `pytest` | developers who want to run the tests |

```bash
pip install --upgrade pip
pip install -r requirements.txt        # just to run
pip install -r requirements-dev.txt    # to run *and* test
```

Version ranges such as `numpy>=1.26,<3` allow bug-fix updates but block a future major
version that might break the code.

Check what's installed with `pip list`. You should only see numpy, pytest and their small
helper packages.

## 1.3 What is git-ignored and why

`.gitignore` excludes:

- `.venv/`: environments are machine-specific. Recreate them from the requirements files.
- `data/`: the MNIST files are downloaded automatically.
- `models/`: trained weights can be regenerated by training.
- `__pycache__/`, `.pytest_cache/`: Python's temporary files.

## 1.4 Verify the setup

```bash
pytest                              # all tests should pass
python -m digit_recognizer.train    # downloads MNIST (~11 MB) and trains
```

`pytest.ini` tells pytest where the tests are and adds the project root to the import path.
